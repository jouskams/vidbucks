# Vidbucks - operating manual for the AI assistant

**What Vidbucks does:** it turns any reference (a YouTube link, a video file, a screen recording, images, a channel, or only a written brief) into an ORIGINAL video that reaches the reference's style and quality level, using the user's own topic, brand and words. It also contains a long-form pipeline (script -> voice -> stickman/doodle scenes -> QA -> packaging) and a metrics advisor. Everything runs locally and free (Remotion + ffmpeg + Python); the AI assistant is the only paid part.
Talk to the user in THEIR language; files, code and JSON stay in English. `AGENTS.md` points here; this file is the single source of truth.

## FIRST RUN: status first, then work
At the start of every session you receive `VIDBUCKS STATUS (<phase>)` from the SessionStart hook; without the hook run `node scripts/status.mjs`.
- `needs_setup` / `needs_smoke_test` -> tell the user what is missing (their language) and run skill **`vidbucks-setup`**: it installs Node/ffmpeg/Python packages, the Remotion agent skills (`npx skills add remotion-dev/skills`), an open-source voice engine (Kokoro, Piper, Chatterbox or OmniVoice, chosen with the user) and Whisper, proves it with a voice test and `node core/tools/smoke.mjs`, records it (`node scripts/status.mjs --mark-ready`) and then ANNOUNCES to the user that Vidbucks is ready and asks for the first reference video.
- `ready` and not yet announced -> tell the user NOW that setup is finished and ask for the reference video (link, file, images or a brief) and what they want to say; then `node scripts/status.mjs --mark-announced`.
- `ready` -> start work. Read this file, `knowledge/learned.md`, and look for work in progress (`core/videos/*/STATUS.md`).
Vidbucks home = the folder with `core/tools/doctor.mjs` + `scripts/status.mjs` + this file (cwd, `$VIDBUCKS_HOME`, or the path in `~/.vidbucks/home`).

## 1. THE GOLDEN PATH (use it for every request that has a reference or a style wish)
Skill: **`vidbucks-reference-to-video`** (read it - it holds the type->route table and the FIX-row->action map).
1. **Reference in** - link, file, channel, images or brief. User directions always override the reference. Several references: analyse each, merge, say which wins where.
2. **Measure** - `python core/tools/analyze_reference.py --file <mp4>` (cuts, shot lengths, palette, brightness, motion, transitions, loudness, tempo, sound hits, curves, transcript, `style_spec.json`, route hints) and/or `--link <url>` (public metadata, captions, thumbnail, channel context, scene proposal). **Link only?** Do not ask for the file: do the link analysis, then a VISUAL PASS in the Browser pane (mobile viewport, `video.currentTime` seeks, small screenshots every ~0.7 s for Shorts), view only, nothing downloaded; say what stays unknown.
3. **Look and classify** - look at `sheet.png` / `thumb.jpg` / a dense frame strip, name the type and the devices (see the route table), decide the route in one line.
4. **Plan** - a scene-by-scene proposal (`scene_plan.md`) rewritten for the user's content; formats (9:16 / 16:9: one responsive composition), duration, voice or not, tempo grid, loudness target = the reference's LUFS.
5. **Collect assets yourself** - Google Images in the Browser pane for visual research (VIEW ONLY, never reuse), licensed media with `fetch-stock.mjs` (specific Wikimedia queries beat Openverse), `cutout.py` for transparent cut-outs, procedural/canvas assets otherwise, the user's own material rebuilt as clean vectors (never pasted as-is). Never ask the user for reference images, photos or analysis.
6. **Build** - start from the closest template in `core/src/templates` (copy a config from `demos.ts`, change content) or write a new composition; voice via `vo_words.py` / `make_narration.py`; music via `make_pulse_track.py` at BPM = 60*n/T so the big moments land on beats; SFX placed on the visual change points.
7. **Measure the result and iterate** - render -> `analyze_reference.py --file <render>` -> `--compare ref cand` -> `--sidebyside ref cand out.png` and LOOK. Fix every FIX row (map in the skill), repeat (about 4 loops). The score never replaces looking.
8. **Deliver** - the files, the score table, credit lines for CC BY assets, what was verified and what was not (you cannot hear audio), and the one thing that would raise quality most.

**The steps are defaults, not limits.** If the reference needs something not in this package (a 3D look, a new transition language, a map, a character, real footage), choose the best legitimate way - new code, procedural assets, licensed media, a connected generation tool the user has - and log the lesson in `knowledge/learned.md`.

## 2. Autonomy and hard rules
- **Ask only user-owned decisions:** language/voice they want, the topic or brand claims when unknown, anything that spends money or touches accounts, publishing, final title/thumbnail choice. Everything else (references, photos, analysis, which tool, which route): decide, act, report in one line.
- **Honesty.** Never claim you heard audio or watched every frame; say exactly what you checked (stills, ffprobe, loudness numbers, scores). Never invent statistics, studies, quotes, sources or results. Fictional characters must be obviously fictional. Say when something is a guess.
- **Legal.** Never download or re-upload other people's YouTube videos (ToS); analyse links via public metadata/captions and viewing in the Browser pane. A file the user supplies is the user's responsibility - measure it, do not redistribute it. No scraping or reusing Google Images (viewing for research is fine). Only CC0 / PD / CC BY / CC BY-SA / Pexels / Pixabay media with credits (`credits.json`; lines for the description); skip NC/ND. No real faces of private people, no athlete/celebrity likeness, no logos, no copyrighted music/footage - use statues, busts, models, objects, silhouettes, procedural art.
- **Keys and accounts.** Never create accounts, never sign in or type passwords for the user. Free API keys are given by the user in chat and stored only via `node core/tools/doctor.mjs --set KEY=value`; never echo them.
- **No publishing.** You prepare files; the user uploads.
- **Cost-aware.** Do the work yourself with the local tools; no parallel sub-agents for a build unless asked. Run long renders in the background and poll the log.

## 3. Route by video type (details in the skill)
kinetic typography -> `KineticType` template · object-metaphor / editorial / monochrome with voice-over -> `ObjectStory` · minimal icon-and-line story with typed captions -> `IconStory` · particle / 3D-scroll look -> `ParticleBloom` (a photoreal subject or a filmed room needs real plates) · product/UI promo -> rebuild the UI as vector components, camera moves · motion-design promo (bento, poster, blocks, line, retro) -> vector primitives on a beat grid · stickman/doodle long-form -> section 5 · character/hand-drawn -> engine characters (`Doomer`, `Face2`, `Meme`) or sourced art · maps/documentary -> `GeoMap` kit · filmed real-world / talking head -> real licensed footage or an honest mock-up, expect a lower score · unknown -> prototype the smallest piece and measure.
`examples/worked-examples.md` shows one finished example per type with scores and lessons.

## 3b. Renderers and voices are pluggable
Measuring, comparing and the fidelity loop need only an MP4. The BUILD step uses the renderer(s) in `.vidbucks/config.json` (`node bin/vidbucks.mjs config get`; default `remotion`): **Remotion** (templates in `core/src/templates`), **HyperFrames** (HTML + GSAP: scaffold with `npx -y hyperframes init`, author with its own skills `/hyperframes`, `check`, `render -o`; see `docs/integrations.md`), or a **custom** tool registered in `.vidbucks/renderers/<id>.json`. Voice: Kokoro / Piper / Chatterbox / OmniVoice or ANY command via `--engine custom --tts-cmd ...`. If the user names a tool you do not know, register it as a custom renderer or voice instead of refusing; when it is not Remotion, do not use Remotion-only commands (`tsc`, `remotion render`) for it. Tell the user about HyperFrames' anonymous telemetry before using it.

## 4. Tools (all local, free; run from `core/`)
- **Reference analysis and gate:** `analyze_reference.py` (--file / --link / --compare / --sidebyside), `cutout.py` (transparent cut-outs without ML), `contact_sheet.py`.
- **Audio:** `vo_words.py` (English voice-over + word times), `make_narration.py` (long form; engines kokoro / piper / chatterbox / omnivoice, Whisper timings, `~` whisper paragraphs), `make_pulse_track.py` (royalty-free mood track at an exact BPM), `stretch_narration.py`, `silent_timing.py`; built-in licence-free sound library: generate it once with `python core/tools/make_synth_library.py` (indexed in `src/audio-lib.json`, used through `src/Sfx.tsx`); extra third-party libraries can be fetched with `fetch-audio.mjs` (each entry keeps its own licence and credit).
- **Media:** `fetch-stock.mjs` (Openverse, Wikimedia; Pexels/Pixabay with the user's free keys), `fetch-audio.mjs`, `credits.py`, `geo_export.py`.
- **Build/QA:** `register.mjs`, `scenekit.py`, `check_anchors.py`, `blank_start.py`, `stills.mjs`, `qa.mjs`, `script_lint.py`, `chapters.py`, `doctor.mjs`, `smoke.mjs`, `make_placeholders.py`, `make_synth_library.py`; repo level: `scripts/status.mjs`, `scripts/setup.mjs`, `bin/vidbucks.mjs`.
- Render: `npx remotion render src/index.ts <Id> out/x.mp4 --codec h264 --crf 16 --concurrency=4`; stills for review: `npx remotion still src/index.ts <Id> out/qa/f.png --frame N --scale 0.4`; loudness: `ffmpeg -af "loudnorm=I=<ref LUFS>:TP=-1.5:LRA=9,alimiter=limit=0.85:level=false"`. Always run `npx tsc --noEmit` before a render.
- Remotion agent skills (installed by setup from `remotion-dev/skills`; start with `/remotion-best-practices`) for anything beyond the templates, plus `docs/motion-rules.md` (our motion rules: curved easing, springs, staggers, layered backgrounds, grain, render-look-fix) before writing new compositions.

## 5. Long-form route (stickman / doodle explainer, 3-10+ minutes)
Modes: INTAKE -> (STUDY) -> TOPIC -> SCRIPT -> VOICE -> BUILD -> RENDER+QA -> PACKAGE -> REVISE -> ANALYZE. Entry: if the user just says "make a video about X", ask the missing questions in ONE message.
- **Decision Card** (`core/videos/<name>/decision-card.json`, copy `core/templates/decision-card.json`): every field is `USER` (confirmed in chat), `RULE` (cite the rule in `knowledge/`) or `UNRESOLVED`. **Nothing is built while a field is UNRESOLVED.** User-owned fields (language, topic, category, audience, length, voice approval, style reference, title/thumbnail final choice, anything that spends money) can only be USER; derived fields (hook length, scene count, music mood, loudness, pacing, thumbnail recipe) must cite a rule. Record decisions in `DECISIONS.md` (append-only).
- Pipeline (details in skills `vidbucks-script`, `vidbucks-longform-build`, `vidbucks-stickman-engine`, `vidbucks-qa-revise`): script (`script.txt`, blank line = scene, no scene > 40 words, `script_lint.py` >= 90) -> 10-second voice sample, user approves -> full narration -> `video.json` + `scenes.json` (generator from `templates/build_scenes_template.py`; read `docs/SCENES-SPEC.md`) -> `register.mjs`, `tsc`, `check_anchors` -> `stills.mjs` and LOOK at every sheet -> render -> loudnorm -> `qa.mjs` -> packaging (`chapters.py`, `credits.py`, 3 titles, description, thumbnail, `packaging.md`, `NOTES.md`). Update `STATUS.md` after every step.
- Retention bar: hook in 5-10 s, a new picture every 3-8 s, no dead air, one sound per meaningful hit, music 0.12-0.25 under voice, loudness -16 LUFS / TP <= -1.5.

## 6. Revision protocol
Feedback -> numbered change list R1..Rn (target, type, impact on timing) -> ask only if ambiguous or user-owned -> change source files only (`script.txt`, `scenes.json`, `video.json`, a template config), never generated files -> cost-aware redo (visual only: stills then render; sound only: remux; script changed: re-narrate + re-time + anchors) -> keep versions (`-v1`, `-v2`) and append to `REVISIONS.md` -> re-run the gates the change can break -> report what was verified. If a revision contradicts a guideline, do it when the user insists and note the trade-off once.

## 7. Metrics advice
Skill `vidbucks-metrics` reads YouTube Studio numbers (CTR, first-30-second retention, average view %, impressions, traffic sources) against `knowledge/metrics-rules.json` and answers continue / wait / intervene / abandon with ONE action. The thresholds are rules of thumb: state when you deviate.

## 8. Memory
Each video folder is the memory (`STATUS.md`, `DECISIONS.md`, `REVISIONS.md`); cross-video lessons go into `knowledge/learned.md` (append: date, what, how it is handled now). Reference analyses live in `knowledge/references/<slug>/` (report, fingerprint, style_spec, scene plan) - reuse them instead of re-analysing.
